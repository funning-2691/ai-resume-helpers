## 1. 背景与目标

### 1.1 背景
求职者普遍存在以下痛点：
- 不知道如何把已有经历描述得更贴合目标岗位
- 简历描述与岗位要求不匹配
- 市面上缺少免费、便捷的简历优化工具

### 1.2 目标
提供一个 AI 驱动的简历优化工具，帮助用户：
- 快速获得针对目标岗位的简历优化结果
- 了解当前简历与岗位关键词的文字覆盖情况
- 在本地回溯历史优化版本

## 4. 功能详情

### 4.1 功能：AI简历优化

| 项目 | 说明 |
| :--- | :--- |
| **功能描述** | 用户输入岗位描述和个人简历，调用大模型 API 返回优化后的简历内容 |
| **输入** | 岗位描述文本、个人简历文本 |
| **处理逻辑** | 将输入拼接为提示词，调用大模型 API（SiliconFlow，模型 Qwen/Qwen3-8B），设置 temperature 参数控制优化强度 |
| **输出** | 优化后的简历文本 |
| **异常处理** | API 失败时前端显示错误信息，不丢失用户已输入内容（输入内容保存在 localStorage） |

**优化强度设计**：

| 强度 | 说明 | 适用场景 |
| :--- | :--- | :--- |
| 保守 | 保留原意，只修正语病、重复与排版 | 简历已较好，只需微调 |
| 平衡（推荐） | 调整顺序、压缩重复内容并优化措辞 | 通用场景 |
| 激进 | 深度重构表达，突出已有经历 | 简历较弱，需要较大表达改进 |

### 4.2 功能：关键词覆盖率

| 项目 | 说明 |
| :--- | :--- |
| **功能描述** | 从 JD 中提取预置关键词，计算简历对这些关键词的覆盖比率 |
| **算法** | 覆盖率 = 命中关键词数 ÷ JD 关键词总数，映射到 0-100% |
| **关键词处理** | 对重复关键词去重；无法识别关键词时显示"暂无可计算关键词" |
| **输出** | 0-100% 的覆盖率与进度条 |

**重要边界**：
- 覆盖率仅反映岗位关键词在简历文字中的覆盖情况。
- 不代表实际胜任程度，也不代表面试概率。
- 历史记录中同样展示覆盖率；无关键词时显示"暂无可计算关键词"。

### 4.3 功能：历史记录

| 项目 | 说明 |
| :--- | :--- |
| **功能描述** | 每次优化成功后自动保存记录，支持查看、删除、清空 |
| **技术方案** | 浏览器 localStorage，键名 `ai-resume-helper:history:v1`，最多保留 10 条 |
| **数据结构** | id、createdAt、title、matchScore、keywordCount、optimizedResume |
| **交互方式** | 点击"历史记录"按钮进入列表，点击单条查看详情 |
| **数据边界** | 仅保存于当前浏览器；清除浏览器数据后无法恢复；不同设备/浏览器不同步 |

## 5. 非功能需求

| 维度 | 要求 |
| :--- | :--- |
| 性能 | 单次优化请求依赖大模型 API 响应时间 |
| 数据隐私 | 用户输入数据仅用于本次优化请求与浏览器本地历史存储，不用于模型训练或分享给第三方 |
| 安全 | 前端不使用 `dangerouslySetInnerHTML`，Markdown 以安全方式渲染，避免 XSS |
| 代码质量 | `npm run lint` 与 `npm run build` 全部通过 |
